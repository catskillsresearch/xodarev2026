# Comparator: what is compared and what it means

Palomar registration: TBD.

`comparator.json` lists Theorems A–D and their refutations, all proved in this repository with no `sorry`
(axioms: `propext`, `Quot.sound`, `Classical.choice`). They are compared in **unwrapped** form
(`SignatureVolatility/Unwrapped.lean`): each `X_unwrapped` states the claim of the library theorem
`X` using only definitions built directly from the Brownian driver `B` — the signature
`Ŵ_t = paperSig2 B 0 t`, its filtration `sigFiltration B`, the volatility `sigVol M B = ⟨ℓ, Ŵ_t⟩`,
the Itô integral `kitItoInt B` and quadratic variation `kitQuadVar B`, the price predicate
`IsSignaturePrice`, and the market `Market` with price `sigPrice` (the Doléans exponential) — and
is proved by applying `X`. The `ProlongedBrownianSetup` / `ItoCalculusKit` packaging does not occur
in the compared statements; the unwrapped definitions agree with the packaged ones definitionally,
and the price agrees pointwise (Doléans representation). The Challenge
(`SignatureVolatilityComparator/Challenge.lean`) is a single file that imports only Lean core
and Mathlib (Palomar CONTRIBUTING §2.4), following the `lyasoff2016` pattern. It is generated by
`scripts/gen_challenge.sh`, which copies every declaration the compared statements depend on
verbatim from `SignatureVolatility/` in source-module order (the unwrapped statements need no
declaration of the vendored `MathFin` or `BrownianMotion` libraries), and
replaces the compared proofs with `sorry`; `scripts/compact_challenge.py` then drops comments,
blank lines and non-target theorem docstrings (definition docstrings stay), hoists common `open`s
and merges adjacent namespaces, to fit Palomar's single-file size limit. Before each source module
listed in `scripts/challenge_reset_modules.txt` the file empties Lean's per-file cache of
auxiliary `_proof_N` lemmas, and `itoWordIntegral_le1` is elaborated with
`bootstrap.genMatcherCode false`, so auxiliary proof and matcher names match the Solution (where
each module is its own file); neither adds declarations or changes any kernel type or value. To check it, run
`bash scripts/compare_challenge_solution_strict.sh` (also run by
`PALOMAR_QUIET=1 bash scripts/compare_challenge_solution_types.sh`). It mirrors Palomar's
`Compare.loop`: starting from the `theorem_names`, it fingerprints every reachable constant in every
namespace (Mathlib and generated `._proof_N` lemmas included; targets by type only) in the Challenge
and in the Solution, and requires the two lists to be identical.

**Nothing is open.** Every paper claim above is either proved at the exact strength of its
Lean theorem, or refuted by a compared Lean negation that claims no more than that negation. The library and `Solution.lean` have no `sorry` (the Challenge's compared
proofs are `sorry` by design), and there are no `axiom` declarations. The earlier
`OpenProblems` packaging has been retired. The false `affine_riccati_duality_mpr`, the iff
`affine_riccati_duality`, the kit constructor `signatureRiccatiKit_of_setup`, `theorem_B_mpr` and
the full `theorem_B` are not in the library; their negations are.

## Why each counterexample works

Full short narratives are in [`Writeup/narratives/`](Writeup/narratives/README.md). Each one
matches its Lean statement. The verbatim outside (Gemini "Carbon") source for the duality
refutation is in [`Writeup/narratives/appendix/`](Writeup/narratives/appendix/carbon_affine_riccati_duality_mpr.md).

- **Theorem 4.2(ii) `←` / Theorem B** (`not_affine_riccati_duality_mpr_unwrapped`; for every model `M` and
  driver `B`).
  - The counterexample is `u₀^(λ) = 2λe_[1,1,1] − λe_[1,0] − 12λ²e_[1,1,1,1,0]`. Lean proves
    `ℛ(u₀^(λ)) = 0`, so `ψ ≡ u₀^(λ)` is a global Riccati solution, and
    `∫ exp⟨u₀^(λ),Ŵ_t⟩ dP ≤ 1`, so the hypotheses of the universal `←` claim hold.
    Lean does not state a theorem that the exponential is a local martingale or that it is
    not a true martingale.
  - What Lean does prove, and uses, is the factorisation
    `E[exp⟨u₀^(λ),Ŵ_T⟩ | ℱ_{t_λ}] = exp⟨u₀^(λ),Ŵ_{t_λ}⟩·v₁(λ^{1/3}W_{t_λ})`, with `v₁ → 0` at `+∞`.
  - If the identity held for some Riccati solution, for every `λ ≥ 1`, then `log v₁` would agree
    almost everywhere with an entire function of exponential type 0 and quartic growth. That
    function would be a polynomial bounded on `(−∞, 0]`, hence constant, which contradicts
    `v₁ → 0`.
  - `not_affine_riccati_duality`, `not_theorem_B_mpr` and `not_theorem_B` follow from it.
    `not_theorem_B_mpr` and `not_theorem_B` carry an additional unused `HypH3` hypothesis.
- **Theorem C** (`not_theorem_C_unwrapped`). Black–Scholes is complete, by Brownian martingale
  representation, since `ℱ^S = ℱ^W`; every Itô integral `∫_0^T φ dW` lies in the closed span of
  elementary integrals (density of simple integrands and continuity of the Itô isometry). But `N^*_S = ∞`, because `L²(ℱ^S_T)` is
  infinite-dimensional while each depth-`N` span is finite-dimensional. So "complete ⇔ `N^*_S < ∞`"
  fails.
- **Proposition 58** (`not_prop58_blackScholes_depth_zero`). `W_T` is a function of `S_T`. The
  events `{W_T ∈ (k, k+1]}` are disjoint and have positive probability, so `L²(ℱ^S_T)` is not the
  constants, and the depth is `∞ ≠ 0`.
- **Theorem D residual** (`theorem_D_residual_hypothesis_fails_unwrapped`). The hypothesis `N^*_S < ∞`
  fails for Black–Scholes, so the clause is vacuous there. The expansion itself is not refuted.
- **Lemma 77** (`not_lemma77_shuffle_estimate`). We have `ℓ^k ⧢ ℓ = (k+1)ℓ^{k+1}`, so
  `‖e_{ℓ^k} ⧢ e_ℓ‖_w ≥ (k+1)w(k)`, against `w(k)w(1)`. No constant works, for any weight.
- **Lemma 78** (`not_lemma78_local_lipschitz`). Take `w ≡ 1` and `u_k = e_{ℓ^{k+1}}`, which has norm 1.
  `ℛ(u_k)` has coefficient `½·binom(2k,k) ≥ k` at `ℓ^{2k}`, so `ℛ` is unbounded on the unit ball.
